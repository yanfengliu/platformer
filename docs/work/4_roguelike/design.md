Core owns src/game.js, src/world.js, new src/roguelike.js and simulation tests. App owns src/main.js, src/style.css, index.html, new src/profile.js and profile tests. Art owns src/render.js and render tests. No worker edits another scope.

src/roguelike.js exports ITEMS (gear definitions), TALENTS (nine talent definitions), and talentBonuses(ranks). Each talent has id, name, branch, tier, cost, maxRank, requires (array of prerequisite IDs), description. Use three branches with IDs vigor/recovery/reserve, edge/tempo/execution, purse/fortune/barter; prerequisites form each three-node chain. Definitions and effects are fixed by core; profile validates known IDs, rank bounds and prerequisites.

createGame(seed, { talents = {} } = {}) accepts purchased ranks, never mutates the argument, and defaults to the old call shape. It adds embers (earned this life), inventory { blade:null, armor:null, charm:null }, pendingLoot:null, shop:null. Slots hold complete gear descriptors { id, name, description, rarity, slot, ...effect fields }. Stat recomputation combines talents, relics and the three slots without stacking replaced equipment. Floor transitions retain run gold, embers, equipment and relics; new runs reset all run resources and apply current talents.

World adds merchants [{ id, x, y, stock }]. Each stock entry is { id, kind:'gear'|'heal'|'flask', name, description, price, item?, sold:false }. Shops have fixed seeded stock and limited purchases. game.shop is the active merchant or null. mode 'shop' freezes simulation. buyShopItem(game, id) returns boolean and validates the complete transaction; closeShop(game) resumes. E interacts near a merchant; only one interaction consumes an edge. Normal game mode values also include 'loot'.

Dropped gear is world.pickups type 'gear', item descriptor, id, x,y,collected. E near gear opens mode 'loot' and pendingLoot references that pickup. resolveLoot(game, take) returns boolean, marks it consumed exactly once, equips by slot if take and resumes. Normal gold/heal pickups collect automatically. Additional consumables use type 'flask' and embers type 'ember'. Embers are run-earned, settled into the profile only at death/victory. Dropped consumables obey capacities. Stock prices and descriptions reflect talent discounts.

New enemy types are 'shield', 'lancer', 'alchemist'. They retain existing actor fields and clocks. Shield defends its front outside recovery and uses an attached moving mace/shield; lancer commits to a telegraphed spear charge; alchemist throws moving vials that become warned, delayed blast areas. attackKind values 'melee', 'charge', 'bomb', 'volley'. All attacks have immutable windupDuration chosen at attack start. Additional fields are elite:boolean, guarding:boolean. Bomb projectiles have type 'bomb', life, fuse, blastRadius, phase:'flight'|'warning'|'blast', x,y,w,h,vx,vy,owner,damage; renderer uses their actual clocks, core owns contact. Art may refine cosmetic fields only after agreeing with core.

Profile storage is app-owned, versioned and validated. It contains only meta currency, purchased ranks, bounded settled run IDs and bounded run history; never a live game or arbitrary object assignment. App uses a unique run ID for once-only settlement. Saved unknown versions are left intact with an explanatory UI message; corrupt values recover safely. Storage unavailable keeps play working and clearly communicates session-only progression. Talent purchase is atomic, persisted once and cannot alter an active run. Available from title and death/victory, with an in-run inventory panel that pauses input. No production debug setters.

UI retains title action fit/click gates, all menus keyboard accessible, pixel font sizes and supported glyphs. New panels scroll within the clipped frame and focus visible controls. Escape closes shop/inventory/talents where appropriate. Profile and inventory appear in the frozen snapshot for verification only. No external dependencies or generated commercial-style assets.
